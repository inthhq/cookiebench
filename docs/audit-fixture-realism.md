# Fixture realism audit

Raw run artifacts are not stored in this repository. The `artifacts/` paths below name files from the original runs and cannot be checked from this checkout.

The September 27 desktop results measure a small local article under a fast desktop profile. They can describe that fixture's behavior, but zero LCP difference does not establish zero loading cost. This audit reviews the fixture sources and frozen consumer `27d9072a1a2dc6bc1310b7c94173f736c3545a1d865af0ed5a36a95f6ff27554`. It does not change existing run envelopes or upstream c15t archives.

The frozen script/headless consumer already uses the Vite HTML transform that renders shared content and CSS before CMP initialization. The older empty-content confound is preserved in its historical evidence and should not be reintroduced when adding external page resources.

The native consent assertions cover configured public state, controlled request admission/execution, and the declared scenarios. They do not certify every cookie, tracker, iframe, storage partition, multi-tab update, SPA transition, consent expiry, or backend durability property. A blocked public configuration is not a product capability failure. CookieYes remains excluded. The original Usercentrics ruleset remains unqualified for this strict opt-in experiment. ## Representative article workload

The current fixture revision uses `article-workload-v1`. Its original courtyard PNG is generated by `packages/fixture-support/scripts/generate-reference-assets.py` from fixed geometry and seed `20260927`. It is 1200 by 640, has explicit HTML dimensions, and uses an Element Timing marker. The source and CC0 dedication accompany its SHA-256 and length in `packages/fixture-support/assets/manifest.json`. The scene's paper grain is image content, not response padding. There are no sleeps or response delays.

Every framework and baseline requests the same hero path. A shared reading-list module fetches 120 article records, sorts and filters them, and renders six related stories. Its topic selector provides useful page behavior. The fixture proxy serves these shared resources with the same MIME types, compression selection, and cache policy for every framework. This controls the added workload's serving policy. Framework bundles retain their server's encoding behavior. The five vendor integrations with HTML injection request identity HTML for both baseline and candidate.

The shared interaction installer is idempotent. Repeated framework effects must not double-register the page action or download the reading-list module twice. The reading-list workload runs after each framework attaches its ordinary page interaction, including the baseline. Optional consent-gated scripts remain a separate minimal workload so their admission and execution records stay interpretable.

Changing page content creates new fixture revision and configuration identities. The earlier minimal fixture remains available in the immutable source-consumer snapshots and retained run envelopes. Those earlier samples must not be pooled with the article workload.

## Profiles

`benchmarks/profiles/desktop.json` retains the earlier desktop geometry, CPU, and bandwidth under the name `desktop-article-v1`. `mobile.json` declares `mobile-article-v1` with a 390 by 844 viewport, DPR 3, touch, explicit mobile Chromium user agent, CPU slowdown 4, 150 ms added latency, 200,000 bytes/s download, and 93,750 bytes/s upload. The bandwidths are 1.6 Mbps and 750 kbps. These are chosen laboratory settings, not a claim to emulate a particular phone or radio.

The mobile user agent is recorded in the profile and must be updated deliberately when the Chromium cohort changes. Both browser context paths must apply touch and user agent consistently. The actual machine and Chromium build remain part of every result. Neither profile changes egress region.

Use a profile by copying it into the run configuration's `profile` object. Keep profile IDs separate in analysis, and use the same profile for each baseline/CMP pair. The declared load window is 5,000 ms in both profiles. Action observations retain 1,500 ms after input. Timeout samples remain incomplete or failed, never zero.

## Browser references

[web.dev's LCP definition](https://web.dev/articles/lcp) explicitly excludes inline SVG elements, while allowing eligible image elements, including an image whose source is SVG. The browser chooses the largest eligible element; the benchmark must retain the selected element and report page-content paint separately when a consent banner becomes LCP.

A representative workload does not make synthetic measurements field Core Web Vitals. Report absolute baseline/CMP LCP, paired differences, measured element, observation deadline, and profile together. Keep banner appearance, public readiness, input response, script gating, and persistence evidence separate so an early page paint cannot hide later consent work.

## Implemented startup topology

Five configured competitors now use a server-injected bootstrap at the documented document position. Cookie Control starts at the end of body; Didomi, Enzuzo, and OneTrust start at the opening head; iubenda starts at the end of head. The fixture server bundles the canonical TypeScript adapter with pinned esbuild before listening. Its streaming HTML transform injects that inline classic script exactly once. The baseline receives no adapter injection. Both documents request identity HTML from Next so the proxy never edits compressed data. Framework script responses keep their existing encoding behavior.

This records document placement while preserving the adapter's existing async remote SDK insertion. It does not claim to reproduce every flag from a vendor account's current generated embed. Public callbacks and the original IDs stay unchanged. The bootstrap installs public state listeners and starts SDK loading at the declared document position without waiting for a React effect. It attaches the privacy control at DOMContentLoaded. These five fixtures no longer import the same adapter into a React effect. Both baseline and candidate initialize the shared page workload through the same Interaction component after hydration. The new fixture revision names the document position and async SDK behavior.

Ketch and Osano keep their documented `next-client-effect` revision until their supported embed guidance is available. Usercentrics stays configuration-blocked and CookieYes stays excluded. The workload changes do not convert either into a qualified measurement.

The new desktop/mobile validation uses a declared five-second navigation-to-observation window for both members of every load pair. Action observations retain 1,500 ms after input. The load window replaces the earlier 1.5-second cohort window for the new workload only. In particular, the mobile image has about 2.47 seconds of transfer time at the selected bandwidth before latency and competing work. Slow/incomplete attempts remain visible.

## Startup verification

Initial production startup evidence (`artifacts/v3-measurement-audit/startup-final/index.json`) records ten browser visits across five built fixtures and their baselines. Every baseline omitted the bootstrap. Each candidate included exactly one at the declared source position, reached public readiness with no explicit choice and no optional grants, and loaded the shared page module/catalog once. All ten visits rendered the 1200-pixel image, initialized the reading list, and produced no page error. The selected LCP element was `IMG#primary-content` in every visit, including OneTrust. These visits used manually assembled proxy commands, which missed a defect in the package start scripts. The measurement matrix exposed that defect; the consolidated audit records its correction and verification through the actual configured commands.

The evidence includes raw HTTP documents, response headers, screenshots, and server logs. Candidate responses omitted the original Content-Length and ETag after transformation. Both documents used identity HTML. Checked assertions (`artifacts/v3-measurement-audit/startup-final/checks.json`) record these outcomes. The earlier startup probe remains alongside the final one and documents the intermediate version with a redundant client import that the final fixture removes.

Focused fixture tests cover PNG identity and dimensions, compressed response parity, idempotent page installation, and stream injection at every split position, including non-BMP text. The [measurement audit](measurement-audit.md) reports the broader consent flows and timed measurements.
