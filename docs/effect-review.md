# Effect and correctness review

This review covered the runner, schema, analysis, PostgreSQL repository, CLI, and controlled reference fixture. It used the installed Effect 4.0.0-rc.117 source and its complete `AGENTS.md`, including resource-acquisition examples. The review examined scope ownership, interruption, typed failures, SQL transactions and retries, pairing, missing evidence, and browser timing boundaries. It did not attempt a stylistic rewrite of working code.

## Corrections

- Concurrent stale-lock recovery could delete a newly acquired lock. A recovery guard now serializes stale-owner inspection and rechecks ownership while holding that guard. A regression holds stale readers until the first replacement owner acquires its lock. The prior implementation admitted two successful owners; the corrected implementation admits exactly one among twelve contenders and releases it on interruption.
- A declared controlled-server evidence endpoint could fail, return a non-success HTTP status, or provide malformed events while the sample passed. The runner now validates the response and records `server-evidence-unavailable`, making the sample incomplete. A browser regression checks the sample and capability status. Unit checks cover HTTP failure, malformed envelopes, invalid events, and successful empty evidence.
- The two-fixture execution order previously alternated because each iteration reseeded a generator and selected from its lowest bit. Both benchmark and overhead runs now use a continuous recorded generator and Fisher-Yates choices from its full fractional output. Measured work remains serial under the process lock.
- Passive network snapshots now retain SHA-256 digests of decoded JavaScript, stylesheet, and JSON response bodies. Reads occur after the frozen measurement window and use the actual browser response, without a second fetch. Missing body reads remain explicit.
- Fixtures can declare `artifactPolicy: "mutable-network"`. Comparisons require complete measured third-party script, stylesheet, and JSON identities in each attempt and unchanged URL/digest sets across the comparison cell. Stable dated evidence permits within-run comparisons. A mutable URL alone does not disqualify the result. Missing identity or observed drift keeps the comparison provisional.
- Native interfaces can declare `acceptPreparation`, `rejectPreparation`, and `withdrawPreparation` selectors before their final commit control. Each step runs once, with no hidden retry. Returning visitors prepare through the same native workflow. A controlled draft-selection fixture checks acceptance, rejection, and returning consent.

Preparation timestamps bound automation calls using browser `performance.now()`. They are not exact user-event timestamps. The final consent timer still begins at the captured trusted input event. Raw diagnostics retain all preparation selectors, their bounds, and preparation-to-effective/dismissal elapsed values. A granular control that persists immediately without a save/dismiss operation does not acquire a synthetic save button; that transaction-style scenario remains unsupported.

## Resource and storage findings

Browsers, contexts, child process groups, and the measurement lock use scoped acquisition and release. Browser calls have a cancellation bridge that closes the page, and enclosing scope cleanup closes the context. Production build/readiness calls use deadlines. The initial review overstated CLI cleanup reliability. Full validation reproduced a detached server surviving CLI exit 130. Playwright's default SIGINT handler closed its browsers and called `process.exit(130)`, bypassing the runner's remaining scope finalizers. Browser launch now disables Playwright's SIGINT and SIGTERM handlers, leaving the CLI's abort controller responsible for interruption and scoped cleanup.

The PostgreSQL layer uses a bounded pool. Ingestion validates its envelope, takes a transaction-scoped advisory lock on run identity, checks content identity, and writes the run plus normalized evidence in one transaction. Changed content under an existing run ID fails. Raw-record triggers reject updates and deletes. The existing real-database regressions passed against a fresh PostgreSQL 17.6 database, including concurrent retries, rollback after partial insertion, immutable records, integer byte storage, and legacy reconciliation. No production database migration or cutover was performed by this review.

Pairing still requires matching run, scenario, pair, attempt, metric unit, and collection method. Failed/incomplete attempts and missing required observations prevent eligibility. Fewer than 30 valid pairs cannot produce an uncertainty interval. Action scenarios do not acquire load-baseline comparisons by substituting missing values with zero.

## Evidence limits and recovery

The remote identity gate deliberately does not remove query parameters or normalize JSON. Dynamic configuration, geo responses, telemetry, or per-visit identifiers can therefore leave a cohort provisional. Distinguishing those fields requires an explicit versioned evidence contract. The current gate covers third-party Script/Stylesheet responses and JavaScript/CSS/JSON content types. It does not claim identity coverage for image/font bytes, first-party proxies, or non-JSON consent configuration. Those integrations need a declared evidence extension before stronger reproducibility claims.

The stale-lock recovery guard fails closed if its owner crashes. If a run reports an existing `cookiebench-v3-measurement.lock.recovery` file in the system temporary directory, first stop benchmark processes and confirm no measured browser workload is active. Remove that guard only after this check, then retry. The main lock's owner PID is checked separately. Automatic guard removal would recreate the ownership race this change prevents.

## Network identity and body-byte regression follow-up

The original collector paired CDP rows with Playwright requests by URL and occurrence order. That is not a request identity. Chromium can expose a CORS preflight in CDP while Playwright exposes only the actual request. In all 30 retained Osano load samples, the Other row for `en-gb.json` received the response digest while the completed XHR row had no digest or unavailable reason. The [retained summary](../artifacts/network-identity-regression/retained-osano-summary.json) records this mismatch. A controlled preflight probe also confirmed that the two event streams expose different request sets. A deterministic preflight-first regression reproduces the retained event order and fails under the original collector.

The original collector also overwrote CDP encoded-body counts with `request.sizes().responseBodySize`. Playwright calculates that value by subtracting its response-header size from transfer size; an unavailable header count can leave the transfer total. A separate regression reproduces a bodyless 204 response changing from zero body bytes to 567 transfer bytes. This defect does not require duplicate URLs.

The collector now reads completed response bodies by the exact CDP request ID, after the frozen measurement window. Redirect hops never reuse the final hop's body. Cached responses can provide a digest through their own CDP identity; unavailable or evicted bodies retain an explicit reason. The first correction preserved positive CDP encoded-event counts and used valid `Content-Length` only when those counts were missing. The exact-body correction below supersedes that size rule. Responses unfinished at the cutoff do not gain later body evidence.

[Three initial regressions failed before the fix](../artifacts/network-identity-regression/unit-before.log). [Sixteen focused unit checks pass afterward](../artifacts/network-identity-regression/unit-after.log), covering duplicate-URL ordering, preflight-first delivery, known-byte preservation, bodyless responses, redirects, cache eviction, missing-size handling, and the fixed cutoff. [Two browser regressions pass](../artifacts/network-identity-regression/browser-after.log). They verify exact gzip bytes against the compressed payload, transfer bytes against compressed bytes plus actual HTTP header bytes, bodyless 204, real preflights, and concurrent distinct responses at the same URL. These are correctness fixtures, not benchmark performance evidence.

Old `encodedBodyBytes`, encoded-body aggregates, response digests, and derived remote-identity eligibility require replacement collection. Existing CDP `transferBytes`, `decodedBodyBytes`, request timestamps, statuses, cache flags, and phase attribution do not use the faulty association. Consent observations and page/input timing metrics also remain independent of it. This does not remove separate fixture limitations, including the earlier script/headless layout shift. Earlier envelopes remain preserved under their original collector hash; no response digests are copied between their rows retrospectively.

## Exact encoded-body correction

A positive sum of CDP `Network.dataReceived.encodedDataLength` events does not establish an exact encoded body size. It can include HTTP chunk framing, and retained remote responses also show sums whose completeness cannot be established. The collector preserves these observations separately as `encodedDataBytes`. They are raw event counts and do not feed encoded-body aggregates.

Explicit bodyless responses have zero body bytes. For other responses, the collector requires successful completion within the frozen observation window and an uncached response. A valid `Content-Length` establishes the encoded body size, even when it differs from the event sum. When `Content-Encoding` is absent or `identity`, the complete observed decoded byte count also establishes the encoded body size. Compressed responses without an exact encoded length remain unavailable, including compressed chunked responses with positive event counts. Redirect hops cannot use an incomplete decoded count to establish a body size. Request identity, transfer and decoded bytes, timing, and consent logic are unchanged.

The [controlled browser regression before the correction](../artifacts/network-identity-regression/chunked-before.log) failed both new cases. An identity response with a 1,672-byte body was reported as 1,684 bytes, including 12 bytes of HTTP chunk framing. A compressed chunked response incorrectly reported 45 event bytes as an exact body size. After the correction, the identity body is 1,672 bytes and the compressed body size is unavailable, while both retain their raw event counts.
