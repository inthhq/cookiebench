# c15t alpha.3 upgrade

The checked-in published-package fixtures now pin `3.0.0-alpha.3`, the latest npm alpha verified on September 29, 2026. The release was published on September 28. This updates script tag, headless script tag, React, Next.js, Vue, Nuxt, Astro, and TanStack Start.

The [registry record](../artifacts/alpha3-upgrade-2026-09-29/registry-release-metadata.json) preserves package versions, publication times, tarball locations, integrity values, and dependency requirements. `@c15t/schema` and `@c15t/translations` remain at `3.0.0-alpha.2`, as required by the published alpha.3 dependency graph. Nuxt uses the native module from `@c15t/vue`. The existing TanStack Router version satisfies the new adapter's peer range, so framework versions remain unchanged.

The fixture revision is `3.1.1-article-v1`. Page content, profiles, observation windows, and declared consent protocols retain their existing definitions. The updated run configurations identify the installed release and the relevant published tarball. Shared lockfile and fixture-support hashes also change current competitor configuration provenance; their releases and scenarios remain unchanged.

Earlier envelopes, source-build archives, and reports remain historical evidence. The source workflow stays pinned to its September 27 commit and does not identify the new npm release. Its workspace-input verification intentionally rejects an old consumer against the updated inputs until a separate source consumer is built. See [source builds](source-build.md).

All seven framework typechecks and production builds passed without integration API changes. The [typecheck log](../artifacts/alpha3-upgrade-2026-09-29/typecheck.log) and [build log](../artifacts/alpha3-upgrade-2026-09-29/build.log) retain the output. Existing Astro/TypeScript and Vue-router/Vite peer warnings remain.

The independent provenance review reproduced all 17 current configuration hashes and verified the eight c15t tarball URLs and integrity values against npm. It also verified all 14 historical source archives against their recorded SHA-512 values. The collector source hash remains `2362a29da5729310bc3cb0aba722ceb8344f9bbf7808c1f3a3c2a5bc9aada772`.

The eight production fixture tests passed. They produced 47 benchmark samples: 46 passed and one retained the explicitly expected Astro returning-visitor failure. Each fixture exercised load, accept, and reject. Astro also exercised a returning accepted visit. Its fresh accept/reject samples now have measured consent-effective and dismissal timings, replacing the alpha.2 failure expectations in the browser test. The [raw fixture envelopes](../artifacts/alpha3-upgrade-2026-09-29/fixture-tests/) retain the individual results. The [command record](../artifacts/alpha3-upgrade-2026-09-29/validation-commands.txt) describes the probes and test invocation.

Astro still renders an initial banner for an accepted returning visitor. Its alpha.3 server code omits the configured `consentCategories` when creating the SSR kernel, while the client passes them. The server therefore evaluates default categories that this fixture does not declare and selects the banner. A [minimal reproduction](../artifacts/alpha3-upgrade-2026-09-29/astro-category-repro.mjs) demonstrates that mismatch with the same accepted records. The browser sample is consistent with a banner flash before the client restores accepted consent; it does not establish persistent visibility or an exact flash duration. The retained `unexpected-banner` assertion detects the initial visibility. See the [review](../artifacts/alpha3-upgrade-2026-09-29/review.md) for package paths and evidence. The fixture uses the documented category configuration; it does not patch the package.

Alpha.3 also enables `reloadOnConsentRevoked` by default. The collector keeps input timestamps and observations in the current document, so navigation during withdrawal can discard them. The targeted runner probes recorded two passing baselines and two incomplete c15t samples: script tag timed out during visitor preparation, and React timed out during browser observation after withdrawal. These attempts supply no valid withdrawal timings and do not establish a consent failure or performance regression.

Separate functional checks using normal clicks verified withdrawal in both script tag and React. Each restored accepted consent before withdrawal, reloaded after withdrawal with a new `performance.timeOrigin`, and restored rejected consent with no allowed optional categories. Neither requested or executed optional scripts after that reload, and neither reported browser errors. The script-tag preparation timeout did not recur in this functional check. Raw evidence is in [script-tag navigation](../artifacts/alpha3-upgrade-2026-09-29/with-c15t-script-withdrawal-navigation.json) and [React navigation](../artifacts/alpha3-upgrade-2026-09-29/with-c15t-react-withdrawal-navigation.json). These checks explain behavior; they do not replace the incomplete runner samples. The upgrade preserves the published reload behavior.

Runner typecheck, all six targeted configuration/provenance unit tests, repository lint, and `git diff --check` passed. Lint first identified quote formatting in the new workspace release exceptions; formatting that file resolved it. The final provenance check reproduced all 17 configuration hashes after browser builds and formatting. Logs are retained alongside the browser evidence. The unrelated full browser suite was not rerun for this dependency upgrade.

Functional checks do not establish a speed improvement. A release comparison requires repeated matched measurements with the same workload, profile, and collector.
